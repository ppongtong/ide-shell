# IDE shell

A VS Code–style web shell: activity bar, pluggable feature plugins, TanStack Router file routes, in-house Workspace & Explorer features, stacked sidebar panels (Explorer + Agent), tabs, breadcrumbs and activity dialogs.

**Live demo:** https://ppongtong.github.io/ide-shell/

**Stack:** React 19.3 · React Compiler 1.0 · TanStack Router (file-based) · Zustand 5 · Vite 8 · TypeScript 6.0 · ESLint 10

```
npm install
npm run dev          # http://localhost:5173
npm test             # Node built-in unit tests (registry, bridge, explorer, workbench, agent)
npm run lint         # TypeScript, React hooks/Compiler rules, folder & contract import rules
npm run build        # tsc + eslint + vite build (fails on any React Compiler bailout)
npm run build:demo   # one self-contained HTML file in dist-demo/ (hash URLs)
```

TypeScript is pinned to 6.0 because typescript-eslint does not support TypeScript 7 yet.

## Folders

```

    router.ts             createRouter({ routeTree })
    plugins.ts            the one list of features to load

  routes/                 thin TanStack file routes → feature pages

    index.tsx             redirect → /workspaces

    workspaces/index.tsx  list
    workspaces/new.tsx    draft creation workbench (pinned Details tab)
    workspaces/$wsId.tsx  staticData.container = 'workspace.detail', ?item & ?panels
    settings.tsx
    $activityId/$.tsx     catch-all for plugin pages (/reports, /reports/q1)
  routeTree.gen.ts        generated by the router plugin — do not edit
  features/               one folder = one self-contained plugin
    workspace/            in-house: workspaces, built-in item types (file, dataset), tabs, editors + workspace contract
    explorer/             in-house: Explorer tree panel + explorer contract (reference example)
    agent/                Agent button + Agent panel (consumes workspace + explorer contracts)
    notebook/             example plugin contributing an Explorer item type + custom NotebookEditor
    reports/              example plugin page with its own sub-views
    settings/             Settings button + page + Keyboard shortcuts dialog
  lib/plugin-system/      the IDE plugin SDK: types, createPluginBridge, registry, ShellLocation
  stores/                 shell-wide state & persistence helpers (shell-store, persist)
  components/ui/          reusable UI: ActivityBarButton, Breadcrumb, Modal, ResizableStack
  styles/
```

## Import & Plugin Contract Rules (enforced by `npm run lint`)

Every plugin lives in `src/features/<name>/` with two explicit public doors:
- `index.ts` — **Host entry** (`app/` and `routes/` import `<name>Plugin` and route pages from here).
- `contract.ts` *(optional)* — **Cross-feature contract** (`createPluginBridge<Snapshot, Actions>()`), the **only** file other `features/*` may import (`@/features/<name>/contract`).

| Folder | May import | Must not import |
| --- | --- | --- |
| `app/` & `routes/` | `@/features/<name>` (`index.ts`), `app/shell`, `lib`, `stores` | deep `@/features/<name>/**` |
| `app/shell/` | `lib`, `stores`, `components` | `features`, `routes` |
| `features/<name>/**` | `lib`, `stores`, `components`, `@/features/<other>/contract`, own relative files | `app`, `routes`, sibling feature internals or barrels |
| `features/*/contract.ts` | `@/lib/plugin-system` | `app`, `routes`, `features`, `stores`, `components`, relative files |
| `stores/` | `lib` | `app`, `routes`, `features`, `components` |
| `lib/` | external packages | everything above it |
| `components/` | external packages | everything above it |

### How plugins read Shell state & share Feature state

- **Shell state (`useShellLocation`, `useRegistry`):** Routes declare `staticData.container` (e.g. `'workspace.detail'`) instead of hardcoding route strings in `lib/plugin-system`. `ActivityBar` toggles `?panels=` generically on the active container route (`to: '.'`).
- **Feature-to-feature state (`createPluginBridge`):**
  - `features/workspace/contract.ts` publishes `{ workspace, isDraft, activeKey, activeItem, openItems }` and `{ showDetails, openItem, closeItem }` via `useLayoutEffect`.
  - `features/explorer/contract.ts` (our reference plugin example) consumes `workspace/contract` to render the tree (auto-revealing `activeItem` ancestors on tab switches and deep links) **and** publishes `{ workspaceId, collapsedIds }` + `{ revealItems, collapseAll, expandAll }`—used by `WorkspaceBreadcrumbs` and `AgentPanel` (`"collapse all"` / `"expand all"`).

## React 19.x features used

| Feature | Where | Why |
| --- | --- | --- |
| `<Activity>` (19.2) | `features/workspace/components/EditorHost.tsx` | Open tabs stay mounted while hidden (keyed per workspace + tab): edits survive tab switches |
| `<Activity>` (19.2) | `components/ui/ResizableStack.tsx` | Hidden sidebar panels keep their state (agent chat) |
| `<ViewTransition>` (19.3) | `features/agent/components/AgentPanel.tsx` | New messages animate in |
| `useEffectEvent` (19.2) | `WorkspaceDetailPage.tsx` | Effects read latest callbacks without extra dependencies |
| Actions: `useActionState`, `useFormStatus`, `<form action>` | `WorkspaceDetailsTab.tsx` | Declarative form validation and pending state |
| `useTransition` + `useOptimistic` | `AgentPanel.tsx` | Messages appear immediately while clearing the chat input right away |
| `use(Context)` | `lib/plugin-system/registry.ts` | Read context cleanly |
| `<Context value>` | `app/app-registry.tsx` | No `.Provider` |
| ref as a prop, ref cleanup functions | `components/ui/Modal.tsx`, `ResizableStack.tsx` | No `forwardRef`; attaches/cleans up DOM nodes directly |
| `<title>` in components | pages | Tab title follows the page |
| React Compiler 1.0 | `vite.config.ts` | Automatic memoization across all 37 components/hooks (build fails on `CompileError`) |

## Add things

| To add | Do |
| --- | --- |
| Built-in Explorer item type (small viewer) | Add editor in `src/features/workspace/editors/` + `itemTypes` entry in `src/features/workspace/plugin.ts` (see `FileEditor`, `DatasetEditor`) |
| Standalone feature item type + renderer | Create `src/features/<name>/plugin.ts` with `itemTypes: [{ type, label, pluralLabel, icon, editor: lazy(...) }]` (see `src/features/notebook/`) |
| Sidebar panel + toggle | a `panels` entry (`container: 'workspace.detail'`) + an activity `{ kind: 'togglePanel', panelId }` |
| Shareable plugin state | export `createPluginBridge<Snapshot, Actions>()` from `src/features/<name>/contract.ts` |
| Full-page activity | an activity `{ kind: 'route', to: '/<id>', page: lazy(...) }` — no route file needed |
| Button that opens a dialog | an activity `{ kind: 'dialog', dialog: lazy(...) }` — gets a `close` prop |
| Core screen with typed URLs | a file in `src/routes/` + an activity whose `to` points at it |

Then add new plugins to `src/app/plugins.ts`. Data in `features/*/api/` is mock data.
